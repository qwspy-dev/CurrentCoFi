# Project launch workspace

Current CoFi's project onboarding is a persisted operating surface rather than a design-only checklist. It turns the first project setup into evidence that can be reused in a Circle grant review.

## What it proves

- The project publishes a bounded public identity with an HTTPS website and optional HTTPS logo.
- The signed-in owner has a user-controlled Circle wallet on Arc testnet.
- USDC is available without extra token setup.
- An optional project ERC-20 is inspected directly on Arc before it becomes part of the workspace.
- Campaign, API key, webhook, and pilot records are counted from Current's database rather than self-reported.
- The project can move directly from setup into a measurable, fully funded campaign.

## Readiness calculation

The workspace reports seven evidence checks: project identity, Arc wallet, project token, campaign, developer key, webhook, and pilot. Project identity and the wallet are required foundations. The optional checks raise the project from initial setup through testnet operation to a complete grant-evidence posture.

The score is not an endorsement of a token or a promise of grant acceptance. It is an auditable progress summary backed by persisted Current CoFi records.

## Security boundary

Token metadata and trust observations are read from Arc through the same inspection path used before campaign funding and claims. Project tokens never authorize wallet access. Circle wallet challenges remain bound to the signed-in user, while API keys, agents, and webhooks retain their existing scoped permissions.
